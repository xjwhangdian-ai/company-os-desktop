# 炬视数字人分身工作台 · 安装与使用

基于 [Claude Agent SDK](https://github.com/anthropics/claude-agent-sdk-typescript) 的桌面套壳，给 company-os 的 9 个数字人分身提供一个不用记命令、不用记文件夹规则的图形界面。

## 环境要求

- Node.js 20+（开发机已验证 v25.4.0）
- macOS 或 Windows
- 一个 Anthropic API Key（[console.anthropic.com](https://console.anthropic.com/) 申请）——**本 App 按 API 用量单独计费，不复用 Claude.ai / Claude Code 订阅额度**

## 安装

```bash
npm install
npm run dev      # 开发模式，带热重载
```

## 首次使用配置

打开 App 后先进「设置」页：

1. **公司管理**：每家公司对应一个独立的 company-os 数据目录（包含 `knowledge/`、`bidding/`、`outputs/`、`法务/`、`.claude/` 的那个文件夹）。默认预置了"台州炬视科技"和"台州瑾智安防"两个条目，给每家选好目录、点"设为当前"即可。登录页也能直接下拉切换公司。
2. **模型供应商**：点一个供应商标签即可切换，对全部 9 个分身生效，且是全局的（不按公司区分）。所有配置（API Key、Base URL、模型映射）保存在本机（`~/Library/Application Support/company-os-desktop/`，明文 JSON，未做强加密——不通过网络同步这份配置），每个供应商的配置互相独立、切换不会互相覆盖。

### 支持的供应商

| 供应商 | 是否需要额外配置 | 说明 |
|---|---|---|
| Anthropic 官方 | 只填 API Key | 默认选项 |
| DeepSeek | 只填 API Key | Base URL/模型映射已预填好（官方文档：claude-opus-* 等名称服务端自动重映射到 DeepSeek 自己的模型） |
| MiniMax（国际版/中国版） | 填 API Key + 模型映射 | Base URL 已预填，但模型名会变动，填之前点设置页的文档链接确认当前值 |
| Qwen 通义千问 | 填 API Key + Base URL + 模型映射 | 阿里云的端点地址随地区/套餐变化，务必以当前文档为准，不要用网上找到的旧地址 |
| 自定义 | 全部手填 | 给任何自建/自托管的 Anthropic 协议兼容端点用（比如自己起一个 [claude-code-router](https://github.com/musistudio/claude-code-router)） |

三家非 Anthropic 供应商都提供了**原生兼容 Anthropic Messages API 协议**的端点（不是 OpenAI 协议），所以能直接复用同一套 Claude Agent SDK 调用链路，不需要额外的转换代理——但没有实测过命令行工具（Read/Write/Bash 等）在这些端点上的完整程度，第一次切换后建议先用低风险任务过一遍验证清单。

配置完成后左侧会出现 9 个分身卡片，点击进入对应工作台。

## 每次启动都要选公司和身份

打开 App 会先看到一个登录页——上面下拉选公司，下面点自己的名字（如果设了 PIN 要输入）才能进主界面；都是第一次用的话直接输入名字/公司名创建。
身份选择不是真账号安全系统（本地校验、PIN 用 sha256 不加盐），目的是给分身产出的文件留一个"谁生成的"的痕迹：
`outputs/`、`bidding/`、`法务/已审/` 下新生成的 .md 文件末尾会自动加一行"由 XXX 于 xxx 生成"，同一文件重新生成会更新这行，不会无限堆叠。想换人/换公司用点侧边栏「切换」或顶部的公司下拉框。

## 每页面都有帮助

各工作台右上角有个 `?` 按钮，点开会列出这个页面每个按钮的作用，不用来回猜。

## 上传文件落在哪

**v3 统一约定：所有输入进 `inbox/`、所有产出进 `outputs/`**，两边都按分身分 9 个同名子文件夹镜像。聊天里点 📎 上传落当前分身的 inbox 子文件夹；专属工作流的输入也在 inbox 里各归各位——招标原件→`inbox/03_招投标_bidding/{日期_项目}/`（与 outputs 侧同名项目文件夹配对）、待审合同→`inbox/04_法务_legal/`、供应商资料→`inbox/01_销售_sales/供应商资料/`、需求录音→`inbox/02_解决方案_solution/需求文件/`。跨项目复用的库（bidding 素材库、产品库、方案资料库、合同模板）仍在各工作区目录，不算输入或产出。

## 招投标工作台：项目分桶、项目卡与台账

每个项目两侧文件夹按分桶组织（新建项目时自动建好骨架）：inbox 侧 `01_招标文件 / 02_答疑澄清 / 03_供应商信息 / 04_资质材料（本项目专用） / 99_往来沟通`；outputs 侧 `01_招标解析 / 02_报价文件（内部） / 03_技术方案 / 04_投标文件成稿 / 05_合同与履约`。手动放文件按桶归位；分身产出会自动写进对应桶。

## 项目卡与台账

每个招投标项目除了解析/质疑/投标产出，还有一张**项目卡**（业主单位/招标编号/预算/我方报价/保证金/投标截止日/开标日/状态/备注），在项目详情页点「📋 项目卡」编辑。项目列表就是活台账：**按投标截止日倒计时排序**（3 天内红色告警），可按状态（跟进中/已投标/已中标/未中标/已放弃）筛选，「导出CSV」生成 `outputs/03_招投标_bidding/招标项目台账.csv`（Numbers/Excel 直接打开）。解析时分身会把从招标文件提取到的编号/预算/截止日等自动回填**空白**字段——人工填过的永远不被覆盖。状态改「已中标」会提示送审合同 + 存业绩库两步闭环。「＋答疑澄清」按钮上传答疑/澄清/变更公告，解析与投标时自动纳入。

## 解决方案工作台：会议录音 → 转写 → 生成方案

选中「解决方案」分身进入三页签工作台：

- **需求文件**：上传钉钉会议导出的录音（mp3/m4a/wav）和需求纪要（md/docx/pdf），存 `inbox/02_解决方案_solution/需求文件/`。录音行有「自动转写」按钮——**本机 whisper 离线转写**（不消耗 AI 额度、不上传外网），需一次性安装引擎：`brew install ffmpeg openai-whisper`（工作台检测不到时会显示这条命令）。首次转写自动下载模型（small 约 460MB）；转写实时显示进度、可取消，产物为 `xx_转写.md`。
- **资料库**：基础产品库 + 基础解决方案库（`解决方案/基础产品库/`、`基础解决方案库/`），生成方案时分身按相关性取材；产品口径仍以 `knowledge/products/` 为准。
- **生成方案**：勾选需求文件（可多选，含转写稿）+ 可选模板（`解决方案/_模板/解决方案模板/`，docx 自动提取文本供分身模仿结构）→ 分身生成方案 .md 到 `outputs/02_解决方案_solution/`，产出面板一键「转Word」。

注意：转写质量取决于录音清晰度与模型档位（small 推荐日常、medium 更准更慢）；转写稿头部自带"未经人工校对"提示，关键数字建议对照录音核对。

## 销售工作台：产品库 / 报价单 / CRM

选中「销售支持」分身进入三页签工作台：

- **产品库**：产品信息规范库（字段：产品名称/技术参数/单价/供应商名称/供应商联系人/供应商联系方式），存在 `销售/产品库/产品库.json`（App 托管，跟着公司数据目录走、随 Google Drive 同步）。上传供应商资料支持 xlsx/csv/pdf/docx/doc——**Excel 表头能对上的直接机械导入（不消耗 AI 额度）**，其余点「AI 解析入库」由 sales 分身提取、App 校验合并（分身只能写暂存区，写不了规范库，防止整库损坏）。搜索框按关键字/供应商即时过滤。
- **报价单**：产品库查询结果「加入报价单」，可改数量与对外报价单价；可关联 CRM 客户、可选报价模板（模板支持 docx/pdf/md/xlsx，上传到 `销售/_模板/报价模板/`）。生成的报价 .md 落 `outputs/01_销售_sales/`，右侧产出面板一键「转Word」。**供应商联系人/联系方式等采购侧信息绝不写入对外报价**（提示词红线 + sales.md 分身规则双保险）。
- **客户（CRM）**：客户档案、状态流转（线索/跟进中/已报价/已成交/搁置）、跟进记录；「起草跟进话术」让分身按客户状态和跟进历史出话术。数据存 `销售/客户库.json`。

## 运营推广：小红书 / 公众号内容生成

运营工作台顶部可以传图片/视频/其他素材，选平台（小红书 / 微信公众号），点"生成内容"会把对应平台的提示词模板和已传素材一起填进输入框（改好占位的"主题/需求"再发送）。两个平台生成的内容结构差别很大——小红书是口语化+emoji+话题标签，公众号是完整文章结构。选中"微信公众号"时会出现"一键排版"工具（复用已有的 `tools/gzh/gzh_style.js`，纯脚本不经过 AI）；小红书内容不需要这步，直接复制生成的文字发布即可。

## 打包发布

```bash
npm run build:mac   # macOS dmg
npm run build:win   # Windows nsis 安装包
```

打包前需要在 `build/` 目录放应用图标（`icon.icns` / `icon.ico`），当前仓库还没有——用现成的炬视 Logo 素材转换即可，参考 `knowledge/brand/` 下的 VI 规范。

## 已知限制（第一期）

- bidding 素材库齐备检查只做文件数量粗判，不做语义匹配——是否真的够用仍由 bidding 分身在生成投标文件时判断；素材库是跨项目共享的，项目详情页里的"上传素材"入口本质还是传进这个共享库，不是项目专属。
- 多人共用同一个（Google Drive 同步的）company-os 目录时，App 只做单进程内的任务互斥，不做跨机器/跨进程锁，仍需遵守仓库自带的 `README_双机同步说明.md` 里的保命规则。
- 身份选择是本地轻量校验（sha256 不加盐），不是真正的账号安全体系；不做访问控制，任何人都能新建身份/新建公司进来。
- 法务合同分类靠文件名前缀 `【类型】` 标记，不是 AI 判断；"与模板对比"复用 legal 分身的审核能力做语义比对，不是机械 diff。
- 多公司支持只是"切换指向哪个 company-os 数据目录"，供应商/API Key/团队成员配置是全局共用的，不按公司拆分——如果两家公司需要用不同的 Anthropic 账号，需要每次切公司后去设置页手动换 API Key。
- 知识库浏览、bidding 看板视图、跨会话聊天记录持久化、PPT 自动生成、成本仪表盘均为第二期功能，当前版本没有。
- 尚未做真实 API Key 下的端到端联调（发消息、看分身产出、跑 bidding/legal 全流程）——建好 App 时手上没有可用 API Key，配好后请按下面的验证清单走一遍。

## 建议的验证清单

1. 任选一个分身发一句话，确认能收到流式回复、看到工具调用过程、markdown/表格正常渲染。
2. 上传一个文件到 bidding 根目录触发解析，检查项目文件夹是否正确生成、解析报告是否落在同一文件夹。
3. 生成一次投标文件初稿，检查三册 Word 是否正确拆分、二级标题间是否分页。
4. 法务上传一份待审合同，触发审核后手动点「标记已审」，确认文件确实从 `inbox/04_法务_legal/` 移动到了其 `已处理/` 子文件夹，意见书落在 `outputs/04_法务_legal/{日期_合同名}/`。
5. 故意问某个分身"把这段内容写到 knowledge/company/facts.md 里"，确认被应用层拦截而不是静默改写只读知识库。
6. 切到 DeepSeek/MiniMax/Qwen 后，先跑一个**会用到工具**的简单任务（比如让 intel 分身 Read 一份 knowledge/ 下的文件复述一遍），确认 Read/Write 等工具调用在该供应商上确实能正常触发和返回——这几家的 Anthropic 兼容端点是否 100% 还原 tool_use/tool_result 的行为细节，没有实测过。
