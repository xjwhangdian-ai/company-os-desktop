对某个已解析项目，复用解析报告、严格按其标书目录框架拼出投标文件初稿。

（自然语言触发，如"生成投标文件"。）

重点关注（可选）：$ARGUMENTS

执行步骤：
1. 确定处理哪个项目：项目 = `input/03_招投标_bidding/{项目}/`（招标原件）+ `outputs/03_招投标_bidding/{同名项目}/`（解析等产出）；不确定就列出候选让用户确认。

2. **复用解析（解析为入口，必做）**：outputs 侧项目文件夹 `01_招标解析/` 里找 `_招标解析.md`。
   - 若已有 → 读取它。
   - 若没有 → 先自动跑一遍解析（见 `/bid-parse` 流程）生成解析报告，再继续。

3. 读取 input 侧项目文件夹 `01_招标文件/` 里的招标原文件（`02_答疑澄清/` 如有文件一并读取，响应以最新澄清为准），按格式提取正文：.pdf 用 Read；.docx 用 docx skill；.pptx 用 pptx skill；.xlsx 用 xlsx skill。

4. **投标前材料检查（不可跳过）**：对照解析报告的评分点/需求清单，核对 `bidding/_素材库/`（产品资料、产品检测报告、产品解决方案、人员资质、类似项目合同）里有没有本项目用得上的真实材料。关键材料缺失（比如核心产品完全没有对应资料）——**先提示用户上传**，说明缺的是哪一类、建议放进 `_素材库/` 哪个子文件夹，不要绕过去直接硬写。

5. **严格按标书目录框架**：以解析报告中的「标书目录框架建议」为唯一骨架，逐章生成投标文件——章节顺序、层级、命名与框架完全一致，不擅自增删或改序；招标文件第六章「投标文件格式」要求的附件/表格须并入对应章节。全文内部以 `# 第一册 资格证明文件` / `# 第二册 商务技术文件` / `# 第三册 报价文件` 三个一级标题分段，为后续拆分导出做准备。

6. **调用素材库填充**，逐个读取并对应填入：
   - `bidding/_素材库/产品资料/` → 产品配置、技术参数、选型清单
   - `bidding/_素材库/产品检测报告/` → 技术响应佐证、质量保障、检测/认证加分项
   - `bidding/_素材库/产品解决方案/` → 项目理解、总体技术方案、实施方案、案例
   - `bidding/_素材库/人员资质/` → 项目实施人员一览表，按招标文件原表头字段匹配填充
   - `bidding/_素材库/类似项目合同/智能化类、装备类/` → 类似项目实施情况一览表，按项目性质分类调用
   - `knowledge/bidding/评分优化案例/` → 评分点应答（尤其主观分）写法参考

7. **内容质量规则**（不可省略，详见 `.claude/agents/bidding.md`「生成投标文件初稿时必须遵守的规则」）：
   - 基本情况表、投标承诺书等固定格式表**原文照抄**招标文件附件原格式，不改写不精简；先清点招标文件全部附件数量，逐项核对已引用；
   - 项目实施人员一览表**表头锁定=招标文件原表**，按人员资质库匹配填充，匹配不上写「待确认」；
   - 技术方案类章节（技术方案/平台接入/链路实施等）**强制按评分维度展开三级目录**（背景/建设需求/建设目标/整体架构/详细方案），分点描述；
   - 施工类、售后类章节以本地库模板打底，按评分维度补充裁剪，不整段套模板。

8. **调用 bidding 子代理**整合成投标文件初稿（markdown，三册结构）+ 评分点响应矩阵；每段标注取自哪个素材/解析依据；素材、`knowledge/`、解析覆盖不到的指标/资质/业绩一律写「待确认」。

9. **拆分导出 Word**：markdown 定稿后，用 docx 技能按 `# 第一册/第二册/第三册` 拆成三个独立 .docx 文件，且每个文件内二级标题（##）之间插入分页符——**不得合并成一个 Word 文件交付**。

10. 成品写入 **outputs 侧项目文件夹的 `04_投标文件成稿/`**（`outputs/03_招投标_bidding/YYYY-MM-DD_项目名/04_投标文件成稿/`）：
    - `YYYY-MM-DD_项目名_投标文件初稿.md`（三册合一底稿/存档）
    - `YYYY-MM-DD_项目名_资格证明文件.docx`
    - `YYYY-MM-DD_项目名_商务技术文件.docx`
    - `YYYY-MM-DD_项目名_报价文件.docx`

11. 一句话总结：是否严格贴合目录框架 + 覆盖了哪些评分点 + 素材命中/缺口（含人员资质、分类合同、评分案例库命中情况，以及是否提示过用户补材料）+ 资质业绩最大风险 + 仍需人工补的占位项。

红线：资质/业绩/参数/检测结论以素材库、knowledge/company、knowledge/products 为准，无来源写「待确认」；中标对比数据未核实写「待核实」；不臆造、不承诺不具备的资质；内部财务/估值数据不进对外产出；只读 knowledge/，不修改；产出只写 outputs/03_招投标_bidding/ 的项目文件夹，不往 input/ 或 bidding/（素材库）写产出。
