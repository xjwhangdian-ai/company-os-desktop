对一个招投标项目做完整解析（评分拆解、资质缺口、标书目录框架、可质疑条款、可投标性）。

（自然语言触发，如"解析招标文件"。）

重点关注（可选）：$ARGUMENTS

执行步骤：
1. 确定处理哪个项目：招标原件在 `inbox/03_招投标_bidding/YYYY-MM-DD_项目名/01_招标文件/` 里（答疑澄清在同项目 `02_答疑澄清/`，一并读取，冲突以最新澄清为准）（桌面 App 上传时自动建夹；手工使用时自己建同格式文件夹放入原件）。有多个项目且任务没点名时，优先取"有原件但 outputs 侧还没有 `_招标解析.md`"的最新项目；仍不确定就列出候选让用户确认。
2. 读取项目文件夹里的招标原文件，按格式提取正文：.pdf 用 Read 直接读；.docx 用 docx skill；.pptx 用 pptx skill；.md/.txt 直接读。
3. 读取模板 `bidding/_模板/招标解析_模板.md` 了解输出结构。
4. 调用 **bidding 子代理**，把招标文件正文 + 模板结构交给它，产出：项目基本信息、废标/否决条款、评分点对照表、资格/资质缺失清单、标书目录框架、关键时间节点、可投标性评估、可质疑条款提示。
5. 成品写入 **`outputs/03_招投标_bidding/〔与 inbox 侧同名的项目文件夹〕/01_招标解析/YYYY-MM-DD_项目名_招标解析.md`**（文件夹没有就创建，项目夹名必须与 inbox 侧完全一致）。
6. 完成后一句话总结：可投标性 + 最大风险 +（如发现不合理条款）建议是否转 `/bid-challenge`。

红线：参数/资质/业绩引用须标来源，无来源写「待确认」；不臆造；不改 knowledge/；产出只写 outputs/03_招投标_bidding/ 的项目文件夹，不往 inbox/ 或 bidding/ 写产出。
