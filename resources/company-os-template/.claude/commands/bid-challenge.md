对某个已解析项目的征求意见稿/招标文件起草一份质疑函。

重点质疑方向（可选）：$ARGUMENTS

执行步骤：
1. 确定处理哪个项目：项目 = `input/03_招投标_bidding/{项目}/`（招标原件）+ `outputs/03_招投标_bidding/{同名项目}/`（解析等产出）。优先找解析报告里「可质疑的不合理条款排查」一节判定"建议转质疑"的项目；不确定就列出候选项目让用户确认。
2. **复用解析（必做前提）**：outputs 侧若没有 `_招标解析.md`，先自动跑一遍解析（见 `/bid-parse` 流程）再继续——质疑必须基于解析结论，不能跳过解析直接质疑。
3. 读取 input 侧项目文件夹 01_招标文件/ 里的招标原文件，按格式提取正文：.pdf 用 Read；.docx 用 docx skill；.pptx 用 pptx skill；.md/.txt 直接读。
4. 读取模板 `bidding/_模板/质疑函_模板.md`。
5. 逐条审读招标文件 + 解析报告的可质疑条款提示，识别**可质疑的条款**：歧视性/排他性条款、指向特定品牌或唯一产品的参数、不合理的资质或业绩门槛、与上位法冲突、评分设置不公等。
6. 调用 **bidding 子代理**，套用质疑函模板，对每个问题点生成「条款出处 → 问题说明 → 法律依据（标注请核对条款号）→ 质疑请求」；同时提醒核对质疑期时效（招标文件里的质疑截止时间）是否还来得及。
7. 成品写入 **outputs 侧项目文件夹的 04_投标文件成稿/**，命名 `YYYY-MM-DD_项目名_质疑函.md`（日期取今天）。
8. 一句话总结：共质疑几条 + 最有力的一条 + 质疑期是否还来得及 + 提醒人工核对法条与盖章。

红线：法条号不得臆造，一律标「请核对具体条款号」；质疑人真实个人联系方式/法代姓名用〔占位〕，不写进产出；只读 knowledge/，不修改；产出只写 outputs/03_招投标_bidding/ 的项目文件夹。
