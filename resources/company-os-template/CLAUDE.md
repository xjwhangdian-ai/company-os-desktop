# 公司操作系统（Company OS）

> 本文件是公司统一口径的唯一根来源。所有子代理（分身）在每次会话自动加载本文件。
> 任何对外产出（标书、文案、方案、制度）都必须遵守这里的约定。

## 一、公司概况

- 公司全称：台州炬视科技有限公司
- 品牌主张：知世界 行天下；产品平台名"知行"，调度中台"知枢 OS（Zhishu OS）"
- 一句话定位：天空地（水）一体化无人装备协同智能平台——让无人系统真正看懂世界、自主行动
- 三大目标市场：
  - To G 执法端：公安、交警、海警、海事、应急消防
  - To G 行业端：电力巡检、水利监测、林草防火、化工安监
  - To B 工业端：汽配、电子、化工、医药工厂（AMR + 关节机器人 + AI 质检）
- 经营范围（工商登记）：技术服务、技术开发、技术咨询、技术交流、技术转让、技术推广；软件开发；人工智能应用软件开发；人工智能理论与算法软件开发；人工智能行业应用系统集成服务；物联网技术研发；信息系统集成服务；智能控制系统集成；人工智能硬件销售；物联网设备销售；智能无人飞行器销售；智能机器人的研发；智能机器人销售；工业机器人销售；智能车载设备销售；可穿戴智能设备销售；数字视频监控系统销售；安防设备销售；安全技术防范系统设计施工服务；企业管理咨询。

## 二、产品矩阵（对外口径以 knowledge/products/ 为唯一来源）

## 四、统一口径（红线，所有分身必须遵守）

1. 公司工商信息、资质：以 knowledge/company/facts.md 为唯一来源。
2. 产品名称、参数、报价：以 knowledge/products/ 为唯一来源。
3. 任何资质、参数、报价、检出率等数字，找不到来源就写「待确认」，绝不编造。
4. 对外文案语气：专业、克制、以客户价值为中心，不浮夸。
5. **敏感信息红线（最重要）**：knowledge/internal/ 目录下为内部敏感信息（个人联系方式、融资与估值、财务预测、团队成员个人信息、股权安排）。
   - 这些信息**严禁出现在任何对外产出**（标书、新媒体、官网、方案、宣传物料）中。
   - 仅当用户在对话中明确要求用于内部用途（如内部融资材料、内部管理文档）时才可引用。
   - 默认行为：对外产出中需要这类数字时，写「（内部数据，对外不披露）」或「待确认」。

## 五、目录与文件约定

- knowledge/：只读资料库。分身只能读取，**禁止修改或删除**。
  - knowledge/company/   公司工商与资质事实
  - knowledge/products/  产品矩阵与参数
  - knowledge/internal/  ⚠️ 内部敏感信息，对外产出禁止引用
  - knowledge/brand/     品牌与文案规范
  - knowledge/bidding/   招投标历史与模板
- **输入/产出统一约定（v4）**：所有工作流（含专属工作流）的**输入进 input/、产出进 outputs/**，两边都按分身分 10 个同名编号子文件夹（`01_销售_sales` … `09_情报_intel`、`10_MBA学习_mba`）互为镜像；**产出一律按项目再建三级文件夹**。跨项目复用的产品库、台账、模板、素材统一收纳在 `libraries/`，既不是输入也不是产出。
- input/：原始输入区，按分身分 10 个子文件夹。桌面 App 上传自动落位，手动丢文件也按同样规则放：
  - `input/03_招投标_bidding/{YYYY-MM-DD_项目}/` → 招投标项目输入侧（与 outputs 侧同名配对），内按分桶：`01_招标文件/`、`02_答疑澄清/`、`03_供应商信息/`、`04_资质材料/`（本项目专用，如合作方资质；公司自有资质在素材库）、`99_往来沟通/`
  - `input/04_法务_legal/` → 待审合同（平铺，文件名带【销售合同/工程合同/其他】前缀；处理完移入 `已处理/`）
  - `input/01_销售_sales/供应商资料/` → 供应商产品资料/投标报价文件原件（喂产品库的原料）
  - `input/02_解决方案_solution/需求文件/` → 需求纪要（md/docx/pdf；本地转写模块已移除，录音先在外部转成文字纪要再上传）
  - 其余分身子文件夹 → 聊天里上传的普通参考文件
- `libraries/03_招投标_bidding/`：招投标**素材库与模板库**（跨项目复用，不放项目文件）。
  - **统一流程**：桌面 App「新招标项目」上传原件 → 落 `input/03_招投标_bidding/{日期_项目}/` → 解析报告/质疑函/投标文件全部产出到 **`outputs/03_招投标_bidding/{同名项目}/`**（两侧同名配对）。
  - **项目卡**：`outputs/03_.../{项目}/项目卡.json`（业主/编号/预算/我方报价/截止日/状态，App 托管禁直写；分身回填走同目录 `_项目卡回填.json`，只补人没填的空字段）。台账 CSV 由 App 一键导出。状态：跟进中/已投标/已中标/未中标/已放弃；**已中标 → 合同送 legal 审 + 签署版存 `_素材库/类似项目合同/` 作业绩库**。
  - **项目内分桶**（App 新建项目时自动建好两侧骨架）：outputs 侧 `01_招标解析/`、`02_报价文件/`（内部成本测算与最终报价，**内容严禁进对外投标文件**）、`03_技术方案/`、`04_投标文件成稿/`（质疑函/投标初稿/三册 docx）、`05_合同与履约/`（中标后副本，业绩主档在素材库）+ 根目录 `项目卡.json`；input 侧分桶见上文 input 一节。答疑/澄清与原件冲突时以最新澄清为准。
  - 生成投标文件前，若项目需要的产品资料/检测报告/类似合同在 `_素材库/` 里缺失，先提示人工上传，不跳过材料核对直接硬写。
  - `_素材库/`：产品资料/产品检测报告/产品解决方案/人员资质/类似项目合同（智能化类/装备类）；评分优化案例在 `knowledge/bidding/评分优化案例/`。
  - `_模板/`：质疑函/投标文件/招标解析三套模板 + 历史中标人工补查清单。
  - 运行前置：人工登录 zfcg.czt.zj.gov.cn 查历史中标；**账号密码绝不写入任何文件/配置/仓库**。
  - `.claude/` 内保留 /bid-parse /bid-challenge /bid-draft 作等效可选快捷命令。
- `libraries/04_法务_legal/`：只放 `_模板/`（审核意见书模板、审核要点清单、`合同模板/{类型}/` 对比基线）。
  - 流程：待审合同在 `input/04_法务_legal/`，说"审一下这份合同" → 《合同审核意见书》产出到 `outputs/04_法务_legal/{日期_合同名}/` → 原件手动"标记已审"移入 `input/04_法务_legal/已处理/`。
- `libraries/02_解决方案_solution/`：只放跨项目库——`基础产品库/`、`基础解决方案库/`、`政策文件库/`、`行业趋势库/`（取材库；**产品口径以 knowledge/products/ 为准，冲突时 knowledge 优先**。政策/趋势两库与行业情报打通：情报工作台可把研报一键转存为线索卡）、`_模板/解决方案模板/`。
  - 流程：需求文件在 `input/02_解决方案_solution/需求文件/`，方案成品产出到 `outputs/02_解决方案_solution/{日期_项目}/`。
- `libraries/01_销售_sales/`：只放跨项目库——`产品库/产品库.json`、`客户库.json`、`报价台账.json`（**App 托管规范库，分身与人工都不要直接改**；报价台账是每张机械生成 Excel 报价单的登记簿，也是后续进销存的单据源头）、`产品库/_待入库/`（分身暂存，App 校验合并）、`产品库/图片库/`、`_模板/报价模板/`。产品库支持同一产品多供应商多条记录（按 品牌+型号 归组比价）。
  - 流程：供应商资料在 `input/01_销售_sales/供应商资料/`，报价成品产出到 `outputs/01_销售_sales/{日期_客户_报价}/`。
  - 红线：产品库里的**供应商联系人/联系方式/成本价是采购侧信息，严禁出现在对外报价等对外产出**中。
- 行政人力：制度/SOP 四状态流转——`outputs/07_行政人力_ops-policy/{01_未审核,02_初审,03_终审,04_定稿}/`；分身起草一律进 `01_未审核/`，状态由人在 App 工作台流转（机械移动），`04_定稿/` 为正式生效版。公司章程等治理文件仍归 legal 产出在 `outputs/04_法务_legal/`，行政人力工作台自动汇集直达链接。
- `libraries/08_财务_finance/`：只放 `财税台账.json`（员工/发薪日/月度任务勾选，**App 托管禁直写**）。流程（替代第三方代账）：票据进 `input/08_财务_finance/票据/{YYYY-MM}/` → App「财务」工作台触发 finance 分身产出记账凭证/报税底稿/工资表到 `outputs/08_财务_finance/{YYYY-MM}_xxx/` → 人工复核后去电子税务局申报。发薪日每月10号 App 自动提醒。红线：只做底稿与试算，正式申报以税务机关口径为准。
- tools/gzh/：公众号一键排版引擎（**自然语言触发**，由 operation 分身用；详见 tools/gzh/README.md）。
  - 写好公众号 .md 后，说"**把这篇公众号排版 / 美化一下这篇推文**" → 跑 `tools/gzh/gzh_style.js` 生成炬视固定风格 HTML → 浏览器「一键复制」粘贴进公众号编辑器。
  - 固定风格的单一来源是 `tools/gzh/theme.js`（炬视 VI 配色），**改全局风格只改它**，不在单篇里改样式。等效快捷命令 `/公众号排版`。
- tools/video-gen/：数字人短视频创意蓝图工厂（由 operation 分身用；详见 tools/video-gen/README.md）。先输出 ChatGPT 图像模型静态关键帧提示词与可审核分镜，再按每镜头导出 Seedance 2.5 / Kling 3.0 图生视频提示词；人工把已选关键帧和提示词上传到视频平台生成动态镜头。分身不读取或保存平台密钥。数字人素材只放 `input/05_运营_operation/_数字人素材/`，蓝图、关键帧、动态镜头与复盘统一归档到 `outputs/05_运营_operation/{日期}_{主题}_数字人短视频/`。
- tools/intel-reports/：研报情报管线（intel 分身用，行业趋势+政策文件；从 sgpjbg.com 抓元数据+下载页链接，不下 PDF；详见 tools/intel-reports/README.md）。launchd 每天 07:20 跑 `run_reports.sh` → `outputs/09_情报_intel/研报追踪/{日期}_研报信息流.json`。凭 Chrome 调试 profile 登录态，账号密码绝不写文件。
- tools/bidding-intel/：招投标每日追踪管线（intel 分身用，原 OpenClaw「黄药师」迁移版；详见 tools/bidding-intel/README.md）。
  - launchd 每天 07:00 自动跑 `run_daily.sh`：抓取浙江政采/台州公共资源/乐采云/台州阳光采购四平台 → 聚合文本+当日 JSON 落 `input/09_情报_intel/招投标每日/{日期}/`。
  - 日报由 intel 分身生成到 `outputs/03_招投标_bidding/招投标每日追踪/{日期}_台州招投标_日报.md`；手动触发说"**生成今天的招投标日报**"或用 `/招投标日报 [日期]`。日报同目录附 `{日期}_候选项目.json`，并在会话里渲染**可点击的项目卡片**。
  - **一键跟进闭环（抓取→感兴趣→招投标→销售支持）**：点日报卡片上的「🎯 推送到招投标跟进」按钮（或说"跟进〈项目名〉"、用 `/跟进项目 〈项目名〉 〈日期〉`）→ 自动建 bidding 项目档（input+outputs 分桶骨架）→ 写 `_项目卡回填.json` 标「**跟进中**」→ 招标文件人工下载后从 App「导入招标文件」归档（网站需登录验证，不做自动下载）→ 更新 `outputs/03_招投标_bidding/招投标每日追踪/跟进台账.md` → 调 sales 分身出客户跟进要点到 `outputs/01_销售_sales/`。后续投标动作接 `/bid-parse` 等既有命令。
  - **工作台人工确认入口**：桌面 App「行业情报」页分三个分类按钮——**招投标信息 / 行业趋势 / 政策文件**。
    - 招投标信息：四平台每日抓取，按 采购意向/意见征询/采购公告/采购结果公告 四类分组；人点「确认跟进」才建项目卡（自动填业主单位/预算金额，政采源自动下载招标文件回填招标编号）；「忽略」记入 `候选项目处理状态.json` 不再出现。
    - 行业趋势 / 政策文件：来自 `tools/intel-reports/`（sgpjbg.com，launchd 每天 07:20），读 `outputs/09_情报_intel/研报追踪/{日期}_研报信息流.json`，按关键词（机器人/AI产业/低空经济）分组，点标题跳报告下载页。只读，不建项目卡。
- outputs/：**按分身分文件夹归档**（01_销售_sales / 02_解决方案_solution / 03_招投标_bidding / 04_法务_legal / 05_运营_operation / 06_品牌_brand / 07_行政人力_ops-policy / 08_财务_finance / 09_情报_intel / 10_MBA学习_mba）。每个分身的成果物放进自己对应的文件夹，详见 outputs/README.md。
  - **分身文件夹下按项目/成果批次再建三级子文件夹**（如 `03_招投标_bidding/2026-06-26_市公安局巡特警智能化装备采购/`、`04_法务_legal/2026-06-29_股权治理/`），不要把文件直接堆在二级分身文件夹下。同一项目的 .md 与对应 .docx/.pptx/.png 等格式放进同一个项目子文件夹。
- 产出命名规范：outputs/〔分身文件夹〕/〔项目子文件夹〕/YYYY-MM-DD_项目名_类型.md（全部分身统一，无例外）

## 六、分身（子代理）一览

共 9 个分身，按组织角色对齐（mba 为个人学习分身，与公司业务隔离）：

| 分身 | 对应角色 | 职责 | 何时用 |
|------|------|------|--------|
| sales | 销售 | 销售话术、对外报价、客户跟进、商务谈判 | 对客户推广/报价 |
| solution | 解决方案 | 产品资料、报价模板、解决方案、技术方案、产品文档/PRD/路线图 | 产品/方案支撑 |
| bidding | 解决方案(招投标) | 招标解析、质疑函、投标文件编写（流水线） | 处理招标文件、投标 |
| admin-legal | 行政法务 | 制度、SOP、招聘人事、内部治理、合同审核、法律风险与合规审查 | 行政制度/人事/审合同/法律材料 |
| operation | 运营 | 新媒体、数字人短视频、线上营销推广、内容运营、发布日历 | 数字人短视频/营销运营 |
| brand | 运营(品牌) | Logo方向、VI、企业文化、官网架构与文案 | 品牌与官网 |
| finance | 财务 | 财税、发票、成本、报销、预算、财务测算 | 财务/财税 |
| intel | 跨职能支持 | 行业趋势、政策、竞品、招标情报 | 情报供料给各分身 |
| mba | 个人·学习 | 浙大MBA课程作业、论文、案例分析、笔记复习（与公司业务严格隔离：学习产出不进对外材料，internal 敏感数据不进作业） | 课程作业/论文/学习材料 |

> 分工要点：solution 是"产品知识源头"，sales 对客户、operation 对外传播、bidding 拼标，都从 solution 取料；**行政法务助手**是统一入口：制度/SOP/人事按行政工作流办理，合同/法律材料按法务审核工作流办理，文件仍分别归档到既有行政人力和法务目录；技术交付/实施由真人承担，不设分身。

## 七、工作流通用要求

- 每次产出完成后，给一句话总结（关键结论 + 最大风险/待确认项）。
- **需人工确认的内容统一用「待确认」或〔待确认——补什么怎么补〕标记**（其余同义标记：待核对/待核实/待补充/待落实）。工作台把 md 转 Word 时会自动将这些标记及其所在括注**黄色高亮**，人工按黄色逐项核即可——所以不要把该标的地方写成模糊的肯定句。
- 不确定的地方主动提问或标注，不替用户做无依据假设。
- 输出结构化，能用表格就用表格，少写空话套话。

## 八、跨主机协作与成果归属

- Mac mini 运行 Codex，MacBook Air 运行 DSH。代码、分身规则、工具和配置只通过 GitHub 分支同步；Syncthing 仅同步 `input/`、`outputs/` 与业务资料库。
- 写入成果前，先执行 `tools/workspace/claim-output.sh codex|dsh outputs/〔分身〕/〔项目或成果批次〕` 领取目录。被领取的目录只允许领取环境写入；交接时保留原目录，并新建 `*_续作/` 目录。
- `input/` 中的上传原件、产品库和财务台账不得由两台主机同时修改。出现同步冲突副本时，立即停止写入，人工确认唯一版本后再处理。
