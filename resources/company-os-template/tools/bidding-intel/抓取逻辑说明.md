# 招投标信息抓取逻辑说明> 对应 App「招投标」工作台的「📡 每日情报」页签（原「行业情报」页招投标信息，已整合过来）。> 抓取代码在桌面 App 主进程（`company-os-desktop/src/main/fs-io/intel-fetch.ts`），> 管理员机另有每日 07:00 的四平台管线（本目录 `run_daily.sh`），两路数据同格式合并去重。## 一、数据源与接口（App 内置抓取，三个纯 HTTP 平台）| 平台 | 接口 | 覆盖公告类型 | 列表接口能拿到的字段 ||------|------|------|------|| 浙江政采（zfcg.czt.zj.gov.cn，政采云） | `POST /portal/category`（分类列表 API） | 采购意向 / 采购公告 / 采购结果公告 / 意见征询 | 标题、采购单位、预算、区划代码、发布时间 || 台州公共资源（ggzy.tzztb.zjtz.gov.cn，工程类） | `POST /EpointWebBuilder/rest/secaction/getSecInfoListYzm` | 采购公告 / 结果公告 | 标题、**区县名**（不含采购人）、链接 || 台州阳光采购（www.tzygcg.com，国企阳光采购） | `POST /siteapi/api/Portal/GetBulletinList` | 意见征询 / 采购公告 / 结果公告 | 标题、**区域名**（不含采购人）、发布日期 |第四个平台**乐采云**需要登录态 Chrome，只在管理员机每日管线里跑，数据落同一目录后一并显示。## 二、筛选与归类规则1. **地域**：浙江政采按区划代码前缀 `3310`（台州）过滤；意见征询类目区划常为空，改用标题/单位里的台州区县词（台州/椒江/黄岩/路桥/温岭/临海/玉环/天台/仙居/三门）判断。台州两平台本身就是台州源，不再过滤。2. **四类归类**：按各平台的栏目/分类 ID 映射到 采购意向 / 意见征询 / 采购公告 / 采购结果公告。3. **公安标记**：标题+单位命中（公安/交警/特警/海警/消防/应急管理）→ 🚨 标红。4. **关键词筛选（2026-07-26 起为抓取硬筛选）**：词库整合自原黄药师管线 `keywords_config.json`——安防/智能化/弱电 42 词 + 警用装备 42 词 + 警用采购部门 19 词，去重约百余词。抓取时只保留 **项目名称/采购单位/区县 命中任一关键词** 的公告（公安标记条目始终保留）；词库在工作台「⚙ 关键词」可**增删改**（点词本身=修改），改词后下次抓取生效，列表标红立即生效。词库存 `outputs/09_情报_intel/兴趣关键词.json`（每台机器独立）。5. **采购意向按「采购需求概况」复筛（2026-08-01 起）**：意向公告的标题常常只写"XX单位2026年X月采购意向"，只按标题筛会漏掉相关意向。对浙江政采的采购意向条目（标题未命中的优先，每轮最多补抓 25 条详情页），用详情页正文（含「采购需求概况」栏）再匹配一轮关键词：命中即捞回保留，并把概况摘要（命中词前后文，最长 120 字）写进条目——工作台每日情报卡片上以「📋 需求概况」展示，搜索框也能搜到概况里的词；「跟进」建档时概况一并写进 `00_情报来源.md`。正文命中公安词的同步补 🚨 公安标记。## 三、字段精确度口径（2026-07-25 修正）- **采购单位只放真正的采购人名称**。台州工程/阳光采购的列表接口拿不到采购人，此前把区县名错填进采购单位（这就是"抓取信息有误"的主因）——现已改为：区县名放**区县**字段，采购单位显示「待确认」，点标题打开公告原文核对。- **预算金额**只来自浙江政采接口的 `budgetPrice` 字段，接口没给就留空，绝不从标题猜。- **中标信息按结果表结构化解析（2026-08-01 修复）**：中标单位/中标金额从公告「三、中标（成交）信息」的结果表里取（总价/投标总价 + 供应商名，多标项全收），**绝不用"金额"两字全局兜底**——旧正则会误抓"六、代理服务收费金额"（此前列表显示 ¥3,504 之类小额代理费的错误来源）。- **结果公告「跟进」= 中标归档闭环（2026-08-01 起）**：点卡片「跟进」→ 自动抓公告详情 → 归档 `outputs/09_情报_intel/中标公告库/{日期_项目}/`（公告原文.html + 中标信息.json + 附件全下载）→ 追加 `中标公告台账.xlsx`：Sheet1 每项目一行（中标供应商/金额/专家名单/采购人代表），Sheet2 **专家索引**每专家×项目一行（采购人代表行黄底）——在 Excel 里筛专家姓名即可查 TA 评审过的所有项目。非政采平台落基础行并提示人工补附件/专家。- **意见征询截止日**：意见征询条目会补抓公告详情页，从正文提取「意见反馈/征询截止时间」（两组正则，提不到显示"待确认"）。这是意见征询阶段的重点日期——错过截止就无法提意见影响采购需求。- 找不到来源的字段一律留空/待确认，宁缺毋错。## 四、去重逻辑（三层）1. **同日去重**：同一天信息流内，`类型+项目名称` 相同只留一条。2. **跨天去重**：政府网站会连续多天挂同一公告——近 3 天任一天已出现过的 `类型+项目名称` 不再新增，只留首次出现那条。3. **状态去重**：「忽略」过的项目名不再出现；「确认跟进」过的不再出现，**例外**是已跟进项目（意向/征询阶段确认的）后续发布正式采购公告时，会置顶高亮提醒一次（跟进升级）。## 五、数据保留策略- **工作台只看近 3 天**：打开「招投标」工作台自动清理超过 3 天的机读 JSON（信息流/候选清单/input 原始抓取），保持列表清爽。- **历史永久留档**：每次抓取的**新增**条目自动追加到  `outputs/03_招投标_bidding/招投标每日追踪/招投标信息台账.xlsx`——每天只增不覆盖（追加前再按 类型+项目名称 与已有行去重，双保险）。意见征询行淡黄底。工作台「📊 信息台账」按钮直达。- 抓取频率：打开工作台自动抓一次，30 分钟内不重复（防刷政府接口）；「刷新」按钮强制重抓。请求间 400ms 礼貌延时。## 六、已知局限- 台州工程/阳光采购的采购人、预算需点开公告原文人工核对（列表接口不提供）。- 征询截止日靠正文正则提取，公告写法不规范时会提取不到（显示"待确认"）。- 乐采云依赖管理员机登录态，成员机上看不到当天乐采云数据属正常。- 招标文件正文需登录下载，仍走「确认跟进 → 项目详情 → 导入招标文件」人工闭环。
